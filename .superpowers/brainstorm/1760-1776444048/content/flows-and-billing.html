User Action Flows — where each happens
⬆ Upload Flow
1
Documents tab — user sees a doc slot with "not uploaded" state
Tab: Documents
↓
2
Clicks "+ Upload" on empty slot → UploadZone modal opens
Modal: UploadZone (existing)
↓
3
File selected → card shows Extracting… spinner
Auto-polls every 3s
↓
4
Extraction done → card updates to Pending Review or Verified
Toast notification fires
↓
5
Overview tab badge updates — chain % increases, validation re-runs
Chain auto-recalculates
👁 Review Flow
1
Overview tab shows "2 pending review" alert badge on Documents tab
Tab: Overview
↓
2
User clicks alert OR switches to Documents tab → sees amber "Review →" button on card
Tab: Documents
↓
3
Clicks "Review →" → ReviewModal opens full-screen: extracted fields on left, PDF preview on right
Modal: ReviewModal (existing)
↓
4
User checks fields → Verify or Reject
↓
5
Modal closes → card status updates in Documents tab → Overview chain recalculates
Toast: "Document verified"
✏ Edit / Re-extract Flow
1
Documents tab — user finds a Verified card with a wrong field
Tab: Documents
↓
2
Clicks ⋯ menu on card → options: Edit Fields, Re-extract, View PDF, Delete
Overflow menu (replaces scattered buttons)
↓
3a
Edit Fields → ReviewModal in edit mode → user corrects values → Save
Modal: ReviewModal (mode="edit")
↕ or
3b
Re-extract → confirm dialog → doc goes back to Extracting → same upload flow from step 3
Confirmation modal → auto-poll
Key insight on the ⋯ overflow menu: Right now each card shows Review, Re-extract, Edit, Delete, View as separate buttons — that's 4–5 buttons cluttering every card. An overflow menu (three-dot) on each card hides secondary actions and surfaces only the primary one: Review → (when pending) or View → (when verified). All other actions live one click away in the menu. This also fixes issue #8 from the first screen.
